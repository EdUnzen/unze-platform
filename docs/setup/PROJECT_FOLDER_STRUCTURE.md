# PROJECT FOLDER STRUCTURE

# Grundprinzip

UNZE verwendet eine modulare,
skalierbare und klar getrennte Projektstruktur.

Ziel:
- saubere Entwicklung
- klare Zuständigkeiten
- modulare Systeme
- bessere KI-Workflows
- bessere Skalierbarkeit

---

# Komponentenstruktur

Komponenten sollen:
- klein
- modular
- wiederverwendbar
- unabhängig

sein.

Keine:
- riesigen Monster-Komponenten
- chaotischen Abhängigkeiten

---

# Naming-Prinzip

Dateien und Ordner:
- klar benennen
- konsistent halten
- logisch strukturieren

Beispiele:
- COMMUNITY_SYSTEM.md
- FEED_SYSTEM.md
- AUTH_USER_SYSTEM.md

---

# Service-Prinzip

Jedes Hauptsystem besitzt:
- eigene Services
- eigene Logik
- getrennte Verantwortlichkeiten

---

# Skalierungsprinzip

Die Struktur muss:
- große Plattformen
- viele Module
- mehrere Entwickler
- AI-Workflows

unterstützen können.

---

# KI-Prinzip

KI-Systeme sollen:
- Projektstruktur lesen können
- Module verstehen können
- bestehende Architektur respektieren

---

# GitHub-Prinzip

Repository soll:
- sauber
- nachvollziehbar
- professionell

bleiben.

Keine:
- wilden Dateiablagen
- unklaren Ordnerstrukturen
- chaotischen Schnelländerungen

---

# Mobile First

Frontend-Struktur priorisiert:
- mobile Komponenten
- PWA-Systeme
- Touch-UX
- Performance

---

# Zukunftsprinzip

Spätere Erweiterungen:
- Designsystem-Bibliotheken
- globale Komponentenpakete
- modulare Plugin-Systeme
- AI-Module
- Community-Erweiterungen

---

# Ziel

Die Projektstruktur soll langfristig
eine professionelle, skalierbare und KI-freundliche Entwicklung
des gesamten UNZE-Ökosystems ermöglichen.
